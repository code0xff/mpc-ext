# 복구

## 전제

- 정상 상태: 확장에 A, B / 서버에 C.
- 복구가 필요한 경우: 확장 셰어 중 하나를 잃었거나, 기기를 통째로 잃어 A와 B를 모두 잃은 경우.

## 시나리오 1 — 확장 셰어 1개 분실

1. 남은 셰어 + 서버 셰어 C로 2-of-3 서명이 가능하다.
2. 사용자 인증 후 서버가 복구 모드 참여에 동의한다.
3. **즉시 키 리프레시**를 실행해 A', B', C'를 새로 만든다. 분실된 셰어는 무효화된다.
4. 리프레시 전까지는 복구 모드로 표시하고, 일반 서명을 제한한다.

## 시나리오 2 — 기기 분실 (A, B 모두 분실)

서버 셰어 C 하나로는 서명할 수 없다. 이 시나리오는 사전 백업 없이는 복구 불가능하다.

- 대응책은 **셰어 export**다 (`export.md`). 온보딩에서 export를 유도하고, 하지 않은 상태를 지속적으로 경고한다.
- export 파일 + 서버 셰어 C로 새 기기에서 복구한 뒤 리프레시한다.
- export는 분실 **이전에만** 만들 수 있다. 이 한계를 UI에서 명확히 고지한다. 숨기지 않는다.

## 서버 측 인증

- 복구 요청은 계정 인증 + 지연 기간(cooling-off)을 거친다. 기본 대기 시간은 운영 정책으로 정한다.
- 복구 개시 시 등록된 채널로 알림을 보내고, 사용자가 취소할 수 있게 한다.
- 모든 복구 시도는 감사 로그에 남긴다 (셰어·비밀 값은 기록하지 않는다).

## 테스트 요구

- 각 셰어를 하나씩 제거한 상태에서의 서명 성공을 테스트한다.
- 복구 중단 시 이전 셰어가 그대로 유효한지(롤백 안전성) 테스트한다.
- 리프레시 후 옛 셰어로 서명이 불가능한지 테스트한다.
